# Проверка ключей перед публикацией

Случайно добавленный ключ может дать постороннему доступ к сервису. Поэтому
проверяем и текущие файлы, и прошлые коммиты: удалённая сегодня строка может
оставаться в истории Git.

## Запустить вручную

Из корня клона на Linux x86-64 с Python 3.10+ и Git:

```sh
python3 tools/check_secrets.py --self-test
python3 tools/check_secrets.py
```

Первая команда проверяет сам детектор на вымышленных данных во временном
репозитории. Вторая проверяет наш курс. При первом запуске нужен интернет:
скрипт скачивает официальный Gitleaks 8.30.1 и сверяет архив и исполняемый файл
с закреплёнными SHA256. Проверенный файл сохраняется в игнорируемом `.toolchains/`.
Установка в систему, sudo, личный токен GitHub и платная лицензия не нужны.

Проверка охватывает отслеживаемые файлы, новые неигнорируемые файлы и полную
историю всех локальных Git-ссылок. Удалённые ветки, которые не были получены
через fetch, в локальной копии проверить невозможно. Неполная история вызывает
ошибку, а не успешный результат. Файлы, исключённые из Git, не являются частью
текущего проверяемого снимка; принудительно добавленный файл будет проверен.

Совпавшие значения и полные отчёты не печатаются и не загружаются в Actions.
При находке показываются только путь, правило, строка и коммит. Есть одно
узкое исключение для ранее проверенного теста: он содержит лишь заголовки
приватных ключей, без тел ключей. Проверяются конкретные байты файла и место
находки, а не исключается весь файл или правило `private-key`.

## Остановить случайный push до отправки

Локальный hook — скрипт, который Git запускает перед push. В новом клоне он
не включается автоматически. Чтобы включить именно для этого репозитория:

```sh
chmod +x .githooks/pre-push
git config --local core.hooksPath .githooks
```

Если в репозитории уже настроены другие hooks, сначала объедини проверки,
а не заменяй свою настройку молча. Hook можно обойти; он не является
серверным запретом. Настройка `core.hooksPath` не публикуется вместе с Git.

GitHub Actions повторяет проверку на push и pull request. Проверка после push
сама по себе не предотвращает первую отправку секрета: данные уже дошли до
GitHub. Для дополнительного запрета включают GitHub Push Protection.
Выпуск установщика также должен пройти проверку до публикации файлов.

Если найден настоящий ключ, сначала отзови или замени его у провайдера.
Удаления строки недостаточно. Сканер не доказывает отсутствие любых секретов
и не заменяет контроль настроек GitHub или проверку сторонних сервисов.

Источники: [Gitleaks 8.30.1](https://github.com/gitleaks/gitleaks/tree/v8.30.1),
[GitHub Push Protection](https://docs.github.com/en/code-security/concepts/secret-security/push-protection).
