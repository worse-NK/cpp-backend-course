C++ Backend — самостоятельное приложение для Linux
=================================================

Это тот же учебник, который открывается на сайте: главы, подсветка кода,
тесты, разборы и встроенные лаборатории. Но теперь внутри установочного
пакета есть собственный движок отображения. Для запуска не нужны Chrome,
Firefox, Python, npm или локальный HTTP-сервер. Интернет для чтения и
встроенных заданий не требуется с первого запуска.

Браузерная версия в roadmap/ остаётся самостоятельной и не переделывается
в приложение. Её исходные учебные данные, стили и интерактивные сценарии
используются обеими версиями. Исходники приложения — в desktop-course/;
сборки и отчёты — в desktop-course/release/.

Установка и запуск
-----------------
Целевая сборка — Debian/Ubuntu, Linux x86_64 (amd64). Проверенная среда
указана в release/verification-1.1.1.json. Совместимость с каждым дистрибутивом
и оконным менеджером не предполагается автоматически.

Из папки с установщиком:

  sudo apt install ./cpp-backend-course-desktop_1.1.1_amd64.deb

Права администратора нужны только для системной установки. Если в системе
не хватает обычных графических библиотек, apt получит их из репозитория:
это может потребовать интернет. Браузер, Node.js и Python устанавливать
для работы приложения не нужно. После установки:

  cpp-backend-course-desktop

Или найди «C++ Backend — учебник» в меню приложений. Запуск — от обычного
пользователя, без sudo. У приложения собственное окно и значок книги с кодом.
Меню позволяет вернуться назад/вперёд, изменить масштаб, открыть программу
курса, лаборатории и страницу «Прогресс и приложение».

Что происходит под капотом
-------------------------
1. Linux запускает исполняемый файл из пакета. Это Electron — оболочка,
   которая включает Chromium и Node.js. Chromium отображает HTML/CSS и
   выполняет JavaScript страниц; Node.js обслуживает системную часть
   приложения. Это не запуск установленного в системе Chrome и не скрытое
   скачивание сайта.
2. Главный процесс Electron создаёт окно, задаёт правила безопасности,
   обрабатывает меню и выбор файла сохранения. Он знает, где лежит учебник.
3. Процесс отображения, renderer, показывает главы и выполняет их логику.
   Он изолирован от главного процесса и не получает Node.js API: учебный
   пример не может произвольно запустить shell или прочитать домашнюю папку.
4. Адрес course://app/ — внутренний протокол приложения, а не интернет-сайт.
   Запрос страницы перехватывает Electron и читает разрешённый файл из
   пакета. Никакой TCP-порт при этом не открывается; DNS и HTTP-сервер
   для чтения учебника не используются. Относительные ссылки и обычная
   история переходов сохраняются.
5. React, подсветка, шрифты и все данные уже находятся в пакете. Сборщик
   проверяет их контрольные суммы. Протокол разрешает только файлы из
   списка публикации; путь ../../ не должен открыть посторонний файл.
6. SQL-тренажёр создаёт отдельный Web Worker — поток выполнения JavaScript,
   которому передаётся локальная SQLite через sql.js. Это не PostgreSQL
   и не сервер. Данные задания создаются заново для каждого запуска;
   черновик запроса сохраняется отдельно. Учебные схемы и другие модели
   также выполняются локально; они не управляют настоящим Kubernetes.

Почему в диспетчере задач несколько процессов
-------------------------------------------
У Chromium многопроцессная архитектура: окно, отображение страниц, графика
и вспомогательные операции могут обслуживаться разными процессами. Это
нормально. Отдельное окно с теорией из вопроса тоже может добавить процесс.
Наличие нескольких строк не означает несколько независимых установок.

Чем это отличается от прежней PWA
--------------------------------
PWA использовала уже установленный браузер и его профиль. Старый .deb
только предоставлял файлы через сервер на 127.0.0.1:47653. После сохранения
копии service worker (браузерный обработчик запросов) мог выдавать страницы
из браузерного кеша. Но движок всё равно предоставлял браузер.

Здесь движок входит в программу. Нет Python-запускателя, HTTP-сервера,
браузерной установки PWA, service worker или требования сначала наполнить
кеш. Поэтому пакет больше, зато открывается как самостоятельное приложение
и не зависит от наличия и версии личного браузера.

Безопасность и её границы
------------------------
Включены sandbox (ограничение доступа процесса к системе), contextIsolation
(разделение контекстов страницы и служебного кода) и обычная webSecurity.
Node.js не включён в renderer и SQL-worker. Политика CSP ограничивает
источники скриптов: собственные файлы и проверенные inline-скрипты курса,
без произвольных удалённых скриптов и без unsafe-eval. Inline-стили
сохранены, поскольку их использует исходный интерфейс; Blob разрешён
только там, где это нужно локальным worker и резервным файлам.

Внешняя статья открывается в обычном браузере только по явному переходу.
Доступ к камере, микрофону, геолокации и произвольному внешнему содержимому
учебнику не требуется. Скачивание своего примера или резервного файла
вызывает выбор пути сохранения; программа не запускает скачанный пример.

Для Linux пакет включает стандартный chrome-sandbox helper, устанавливаемый
root:root с режимом4755: это штатный резервный механизм песочницы Chromium,
не требование запускать учебник через sudo. Нельзя обходить проблемы
песочницы флагами --no-sandbox или отключением webSecurity. Дистрибутивы
могут иметь дополнительные ограничения AppArmor/user namespaces; при
ошибке нужны диагностика и совместимый способ установки, а не снятие защиты.

Electron — не абсолютная гарантия безопасности. Вместе с учебником мы
поставляем движок и обязаны обновлять его при исправлениях уязвимостей.
Поэтому нельзя бесконечно оставаться на одной версии оболочки, даже если
теория курса не меняется. Встроенного фонового автообновления пока нет:
новая проверенная версия устанавливается новым .deb.

Где сохраняется прогресс
-----------------------
Страницы используют прежние ключи localStorage: например
cpp_station0_progress_v1, cpp_course_last_read_v1 и cpp-sql-lab:v1:expression.
Но сами данные теперь принадлежат собственному профилю приложения.
Типичное место в Linux:

  ~/.config/cpp-backend-course-desktop/

При переопределённом XDG_CONFIG_HOME место может отличаться. Программа
не хранит прогресс рядом с бинарником в /opt и не требует прав записи в
установочную папку. Обновление .deb не меняет постоянный профиль и адрес
course://app/, поэтому не должно обнулять отметки.

Прогресс браузерного сайта, file:// и старой PWA автоматически не читается.
Это отдельные профили и адреса. На странице «Прогресс и приложение» есть
экспорт/импорт того же JSON-формата и закладка для экспорта со старого
адреса. Перед восстановлением можно сохранить нынешние данные. Восстановление
выполняется только после проверки и подтверждения, не затрагивает чужие
ключи и не выполняет содержимое файла как программу.

Экспортируются записанные результаты, отметки, размер текста и SQL-черновики.
Незавершённая попытка теста, как и прежде, живёт в открытом окне. Заверши
её перед закрытием приложения. Самостоятельно сделанный JSON не является
сертификатом или защищённым от изменений результатом экзамена.

Что остаётся отдельным практикумом
---------------------------------
Исходники C++, SQL и учебные pcap входят в пакет. Но компиляторы, реальные
базы данных, Wireshark, Docker, Kubernetes, серверные контейнеры и VM —
отдельные программы. Учебник не устанавливает их и не выполняет команды
из главы. Внешние источники и получение таких инструментов требуют сети.
Отсутствие установленного браузера не мешает самому учебнику, но внешнюю
статью без браузера открывать будет нечем.

Удаление и старая версия
-----------------------
Старая PWA-сборка удаляется отдельно от браузерного курса. Если старый пакет
cpp-backend-course-offline действительно установлен, новый пакет с ним
конфликтует: apt предложит заменить старый запускатель. Он не должен
удалять профиль личного браузера. Уже установленную браузерную PWA удаляют
через браузер; не очищай её данные до экспорта прогресса.

Удалить новое приложение:

  sudo apt remove cpp-backend-course-desktop

Профиль с прогрессом намеренно остаётся; его удаление — отдельное осознанное
действие после резервного копирования. Обычное закрытие приложения завершает
его работу, не оставляет Python-сервер и не запускает службу при загрузке.

Сборка из исходников
-------------------
Понадобятся Python3, dpkg-deb и полученный официальный Electron runtime:

  python3 desktop-course/fetch_runtime.py --version 45.2.3 --output desktop-course/.toolchain/electron-45.2.3-linux-x64
  python3 desktop-course/build_site.py
  python3 desktop-course/build_deb.py --site desktop-course/release/site --runtime desktop-course/.toolchain/electron-45.2.3-linux-x64 --output desktop-course/release --version 1.1.1

Получение runtime — отдельная сетевая операция с проверкой опубликованной
SHA256 и закреплённого значения. Повторная сборка из уже полученных файлов
не требует npm install, Node.js в системе или подключения к интернету.
Все лицензии Electron/Chromium и локальных зависимостей входят в пакет.
