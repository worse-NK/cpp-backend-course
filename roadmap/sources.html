На что опирается теория

Объяснения, аналогии и учебные задачи написаны для этого курса. Ссылки ниже позволяют проверить правила и углубиться в детали; они не означают, что текст дословно взят из источника.

Как читать ссылки

  • Правила C++. N4861 — открытый рабочий проект стандарта C++20, не опубликованное издание ISO. HTML на timsong-cpp.github.io — удобное представление текста. Текущий draft на eel.is изменяется и может описывать более новые версии языка; для спорного правила C++20 нужна сверка с соответствующей редакцией.
  • Проектирование. C++ Core Guidelines — рекомендации под редакцией Бьёрна Страуструпа и Герба Саттера, а не обязательные требования языка. Их применение зависит от ограничений программы.
  • Сети и HTTP. RFC следует читать вместе с областью применения, обновлениями и errata. RFC 9293 описывает TCP, RFC 9110 — семантику HTTP; устройство конкретного сервера ими полностью не определяется.
  • Инструменты и реализации. Документация CMake, Git, Boost.Asio, Linux man-pages и ABI описывает соответствующие инструменты или платформы. Свойства Linux или конкретного ABI нельзя автоматически переносить на все реализации C++.
  • Практика backend. OWASP, Google SRE и рекомендации по API помогают обсуждать угрозы и компромиссы. Учебная архитектура — пример применения, а не единственно допустимое решение.

Это указатель ссылок из теории, а не отметка о завершённой построчной экспертизе. Наличие ссылки не доказывает корректность каждого утверждения. Если прямой ссылки нет, это явно отмечено: такой раздел нельзя считать проверенным только по этому указателю.
