# Один JOIN, разные исполнители; память и статистика

Программа показывает задачи вместе с именами владельцев. Для одного и того же
ответа база может перебирать пары, строить хеш-таблицу или сливать упорядоченные
потоки. Затем опыт создаёт 100 000 учебных строк и меняет распределение владельцев,
чтобы отделить влияние статистики от влияния памяти сортировки и агрегирования.

Нужны PostgreSQL 18 и `psql`. Используйте только свою локальную учебную базу,
не общий рабочий сервер. Таблицы TEMP доступны лишь этому соединению; постоянные
данные и серверные настройки не изменяются. Сценарий создаёт десятки мегабайт
учебных данных и может записывать временные файлы. Запрос ограничен 20 секундами;
это не общий лимит всего сценария и не ограничение потребления памяти контейнера.

Из корня локальной копии курса, заменив имя учебной базы:

```sh
psql -X --set=ON_ERROR_STOP=1 --dbname=YOUR_LOCAL_TRAINING_DATABASE --file=roadmap/examples/query-execution/run.sql
```

`run.sql` включает файлы в одном соединении. `join-query.sql` возвращает
`10|Anna`, `11|Anna`, `12|Bo` (разделитель зависит от режима вывода psql).
Задача 13 не находит владельца 3 и отсутствует в INNER JOIN.

В `joins-plans.sql` два альтернативных способа временно отговаривают планировщик
выбирать другие JOIN. `SET LOCAL` действует лишь до COMMIT/ROLLBACK. Это опыт для
чтения узлов, а не рекомендация запрещать алгоритмы в рабочем сервере. Флаги не
гарантируют любой заранее нарисованный план. Сравните фактические узлы, outer/inner
входы, Actual Rows и Actual Loops. JSON выбран для однозначных имён полей, а не
как новый формат данных приложения. Здесь TIMING OFF убирает таймер каждого узла,
но сохраняет фактические строки, повторы и итоговую длительность выполнения.

В `statistics.sql` первая выборка реально возвращает 100 строк. После UPDATE
вторая и третья возвращают по 90 010. Между ними меняется только статистика от
ANALYZE; оценки и выбранный путь могут измениться, но не ответ. Это не обещание
фиксированной оценки или обязательного отказа от индекса.

В `memory-plans.sql` сравните Sort Method/Sort Space Type/Sort Space Used,
Temp Read Blocks/Temp Written Blocks; у HashAggregate — HashAgg Batches,
Peak Memory Usage и Disk Usage. Если нужного узла нет, назовите фактический узел,
а не считайте пропущенное наблюдение подтверждением. Низкая память часто даёт
external merge и несколько пакетов хеша, большая может убрать временные файлы.
Точный метод, число пакетов, объём и миллисекунды зависят от версии и среды.

Не складывайте все BUFFERS по дереву как независимые чтения: родитель включает
работу потомков. Для TEMP-таблиц `local` обозначает страницы таблиц этой сессии;
`temp` — временные рабочие файлы операций. Это разные категории. Один `work_mem`
не является потолком RAM базы: есть несколько узлов и одновременно работающих
запросов, хеш-множитель и другие структуры памяти.

Выйдите из psql: TEMP-таблицы и настройки сессии исчезнут. Ничего удалять в чужой
базе и менять в глобальной конфигурации не требуется. Сценарий не является
нагрузочным тестом сервиса и не устанавливает безопасное число клиентов.
