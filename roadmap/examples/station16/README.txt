Станция 16: локальные примеры
===========================

history_checker.cpp
-------------------
Полная программа C++20/23. Проверяет ограниченные завершённые истории одной
ячейки с начальным значением 0. Не больше восьми операций; отдельные порядковые
номера событий. Не анализирует pending-операции, сетевой кластер или SQL.

В отдельной учебной папке:
  g++ -std=c++20 -Wall -Wextra -Wpedantic history_checker.cpp -o history_checker
  ./history_checker
Для C++23 замените c++20 на c++23. Не затирайте нужный исполняемый файл.

Ожидаемый вывод:
  fresh: yes
  stale: no
  overlap: yes
  new_then_old: no
  all checks passed

workflow_recovery.py
--------------------
Python 3, только стандартная библиотека, включая sqlite3.
Запуск без аргументов:
  python3 workflow_recovery.py

Модель создаёт собственный TemporaryDirectory с двумя отдельными SQLite-файлами,
orders.db и provider.db, а затем удаляет только этот временный каталог.
Реальных платежей, сети, секретов и рабочих баз здесь нет.
--worker используется только внутренними дочерними процессами.

Первый процесс фиксирует условный pay:731 на 2500 единиц и намеренно завершает
работу с кодом 75 до сохранения результата у orders. Это заданная точка остановки,
не имитация аварийного питания или повреждения данных.
Второй и третий процессы восстанавливают тот же исход без второго платежа.
JSON-отчёт должен показать:
  before: payments=0, state=pay_pending
  unknown_outcome: payments=1, state=pay_pending
  after_recovery: payments=1, state=paid, payment_id=1
  after_repeat: то же состояние
  changed_amount_rejected: true
  all checks passed

SQLite здесь служит локальному учебному опыту с отдельными транзакциями.
Это не проверка PostgreSQL, платёжного API, произвольной конкуренции,
дискового отказа, безопасности внешнего партнёра или промышленного workflow.
Если сохраняете stdout в файл, выбирайте новое имя и не затирайте нужные данные.
