# Организации, участники и история задач

Небольшая программа помогает двум организациям вести проекты. Один человек может
участвовать в нескольких организациях, а задачи назначаются участникам своего
проекта. Опыт проверяет, какие неверные связи отвергает схема и почему сохранённое
имя автора события отличается от его текущего имени.

Нужны PostgreSQL 18 и его клиент `psql`. Работайте только со своей локальной
учебной базой, не с рабочим сервером. Все таблицы временные: они видны лишь одному
соединению и исчезнут после его закрытия. Файлы не создают роли и не меняют
постоянные таблицы. Это не эксперимент по разграничению доступа: роль, создающая
эти временные таблицы, сама ими владеет.

Из корня полной локальной копии курса, заменив `YOUR_LOCAL_TRAINING_DATABASE`
именем своей учебной базы:

```sh
psql -X --set=ON_ERROR_STOP=1 --dbname=YOUR_LOCAL_TRAINING_DATABASE --file=roadmap/examples/sql-design/run.sql
```

`-X` исключает настройки из личного файла запуска psql; `ON_ERROR_STOP` останавливает
сценарий при ошибке. `run.sql` читает остальные файлы относительно своего каталога.
Не запускайте каждый файл новым соединением: временные таблицы между ними не живут.

`observe.sql` выдаёт три задачи: `(1,100,7,10,Review API)`,
`(1,101,7,NULL,Unassigned)`, `(2,100,7,20,Review website)`. Вторая выборка содержит
участие `(1,10)`, `(1,20)`, `(2,20)`.

В истории останется имя `Anna`, хотя текущее имя станет `Anna New`, а участие —
неактивным (`false`, в текстовом выводе PostgreSQL — `f`). Последняя выборка выдаст `new_task_count = 0`: показанный
путь назначения проверил активность под блокировкой. Отдельный прямой INSERT
с корректными ссылками сам по себе не проверяет active. Посторонний HTTP-клиент
не становится авторизованным из-за правильного внешнего ключа.

История здесь — обычная таблица приложения, не защищённый от владельца базы аудит.
Ручной `event_no=1` допустим только в этом одиночном опыте; это не генератор
конкурентных номеров. Политики удаления, срок хранения и права на изменения
согласовываются отдельно. Выход из psql — достаточная уборка.
