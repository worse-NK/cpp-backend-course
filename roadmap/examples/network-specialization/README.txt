Необязательная сетевая лаборатория: VLAN, STP, OSPF и BGP
=======================================================

В офисе два коммутатора разделяют рабочие и гостевые устройства. Резервный
кабель должен пережить отказ, но не создать петлю. Дальше три маршрутизатора
выбирают внутренний путь, а наша автономная система — одного из двух внешних
соседей. Эта лаборатория последовательно проверяет все четыре механизма.

Здесь не настроечная инструкция для домашнего роутера и не стенд Интернета.
Настоящие bridge, VLAN и FRR работают ТОЛЬКО внутри новой diskless QEMU-VM.
У VM нет сетевой карты, диска и общего каталога с хостом. Сетевые пространства
и ip/bridge/sysctl запускаются гостевым кодом, не скриптом подготовки на хосте.
Не запускай guest.py напрямую, не копируй из него команды на рабочую машину.
Для чтения главы запуск вообще не нужен; это дополнительная практика.

Проверенная среда подготовки: Ubuntu 24.04 amd64, Python 3.12, iproute2 6.1,
QEMU 8.2, glibc 2.39, статический busybox. Нужны уже доступные python3, curl,
dpkg-deb, depmod, ldd, ip, bridge, bash, env, busybox, kmod,
qemu-system-x86_64. Подготовка копирует их runtime-зависимости в новую VM.
Она не является универсальным упаковщиком для любой ОС или дистрибутива.
При отсутствии инструмента остановись; эта инструкция не устанавливает ничего
глобально и не просит sudo. Для иной среды используй отдельную Ubuntu-VM
или прочитай подготовленные таблицы в главе без выполнения лаборатории.

Внутри этой единственной offline-VM локальный VTY-интерфейс FRR доступен её
root без PAM-проверки: vtysh.conf содержит username root nopassword.
Это документированная настройка FRR, а не рецепт защиты рабочей системы.
Она нужна, чтобы не копировать пароли и PAM-настройки хоста в учебный образ.
Никакого SSH-сервера и внешнего сетевого входа у образа нет. Не переноси
эту настройку на хост или настоящие маршрутизаторы. Основание:
https://docs.frrouting.org/en/stable-8.4/vtysh.html#pam-support-experimental

В один учебный каталог скачай эти четыре файла и эту инструкцию:
  build_vm.py
  run_vm.py
  guest.py
  init.sh

Подготовка входных архивов (около 60 МБ). Новый каталог используется только
для этого опыта. Ни один пакет не устанавливается на хост:

  task_vm=$(mktemp -d /tmp/course-optional-net-vm-XXXXXX)
  curl --fail --location --proto '=https' --tlsv1.2 --connect-timeout 10 --max-time 120 \
    --output "$task_vm/kernel.deb" \
    https://archive.ubuntu.com/ubuntu/pool/main/l/linux/linux-image-6.8.0-142-generic_6.8.0-142.142_amd64.deb
  curl --fail --location --proto '=https' --tlsv1.2 --connect-timeout 10 --max-time 120 \
    --output "$task_vm/modules.deb" \
    https://archive.ubuntu.com/ubuntu/pool/main/l/linux/linux-modules-6.8.0-142-generic_6.8.0-142.142_amd64.deb
  curl --fail --location --proto '=https' --tlsv1.2 --connect-timeout 10 --max-time 120 \
    --output "$task_vm/frr.deb" \
    https://archive.ubuntu.com/ubuntu/pool/main/f/frr/frr_8.4.4-1.1ubuntu6.7_amd64.deb
  curl --fail --location --proto '=https' --tlsv1.2 --connect-timeout 10 --max-time 120 \
    --output "$task_vm/yang.deb" \
    https://archive.ubuntu.com/ubuntu/pool/main/liby/libyang2/libyang2t64_2.1.30-2.1ubuntu0.1_amd64.deb

После каждой команды проверь успешный выход; при ошибке дальше не продолжай.
build_vm.py самостоятельно проверяет SHA256 всех архивов ДО распаковки:
  kernel  51772494d46f23d0fad486c7bcd59e21727ec59b9b1894f9c6b4d61ca1899d3c
  modules ee4feb479079151441883b451f0e627df040798c2524641486ce0a90a3811c20
  frr     ccedcc8a053756575bd9f8935be012080eb70091991afd8bb44c95bd51267a20
  yang    ee00c785b39db8e2da6f2e8d43cffcb501b5a6c7e54bebc64ee34918cc869e21

Это фиксированные входы по подписанным метаданным Ubuntu APT, проверенным
2026-11-05. Если зеркало позднее удалит архив, не подменяй его молча другой
версией: потребуется отдельно обновить набор, SHA256 и проверку лаборатории.
Сами SHA из неизвестного письма не заменяют доверенного источника пакета.

Собери образ и запусти только его:

  python3 build_vm.py "$task_vm" \
    --kernel-deb "$task_vm/kernel.deb" --modules-deb "$task_vm/modules.deb" \
    --frr-deb "$task_vm/frr.deb" --yang-deb "$task_vm/yang.deb"
  python3 run_vm.py "$task_vm"

Ожидание ограничено 240 секундами. Используется 1 виртуальный CPU, 512 МБ,
эмуляция TCG без KVM и без sudo. После опытов VM выключается, все её маршруты
и процессы исчезают; файлы подготовки в task_vm остаются для проверки.
Не запускай одновременно много экземпляров. Если запуск закончился ошибкой,
это НЕ успешная проверка: прочитай последние сообщения, не меняя хост.

Четыре проверки, а не заранее сгенерированные правильные ответы:

1. VLAN: A и B в VLAN 10 по разные стороны trunk; C в VLAN 20. Все адреса
   намеренно из одной /24. A->B проходит, A->C нет. Удаление VLAN 10 с trunk
   S2 ломает A->B; восстановление членства возвращает доставку. Сохраняется
   настоящая таблица VLAN до изменения. Отрицательный ping не интерпретируется
   сам по себе без известного обратимого изменения и таблицы.

2. STP: три kernel bridge соединены треугольником; STP включён до его поднятия.
   Приоритеты 4096/8192/12288 и стоимости 10 выбирают S1 корнем. До отказа
   S3->S2 blocking, S3->S1 forwarding. После разрыва S1->S3 резерв S3->S2
   переходит в forwarding; проверяется доставка между клиентами S1 и S3.
   Это КЛАССИЧЕСКИЙ STP, не RSTP. Таймеры 200/100/600 в clock ticks данной
   среды сокращены для урока, не рекомендованы для реальной сети. Замер времени
   ограничен этой VM и не является SLA физической сети.

3. OSPF: A-B=10, B-C=10, A-C=50. Настоящие zebra/ospfd FRR 8.4.4 строят путь
   до 203.0.113.33/32 у C. До отказа next hop A равен 192.0.2.2 (B), после
   отключения B-C — 192.0.2.10 (C). Проверяются маршрут FRR, маршрут ядра
   и ping. Для итоговой метрики префикса учитывается его объявленная стоимость,
   а не только сумма до маршрутизатора C. Hello 1 с / dead 4 с — условия опыта.

4. BGP: A (AS 65000) принимает префикс от B (AS 65010) и C (AS 65020). B объявляет
   AS_PATH 65010 65010 65010, C — 65020. У A входная политика задаёт B local
   preference 200, C — 100. При равных более ранних критериях выбран B несмотря
   на длинный AS_PATH. B отзывает префикс; выбран C. Выбор FRR подтверждается
   ядром и ping. Фильтры экспорта ограничены одним учебным префиксом.

Строки EVIDENCE_* содержат реальные наблюдения JSON. Последняя строка
COURSE_OPTIONAL_VM_EXIT=0 означает, что все явные assertions прошли.
При отказе одного assertion успех не печатается. Вывод включает адреса и
атрибуты только собственного стенда. Предварительно подготовленные данные
не выдаются за захват трафика или эксплуатацию реального оператора.
Полная консоль сохраняется в новом приватном console-*.log внутри task_vm;
run_vm.py печатает его путь. Диагностический --only ospf или --only bgp
проверяет только один сценарий и не является полной приёмкой четырёх опытов.

Для самостоятельной работы сначала предскажи последствия, затем измени
ТОЛЬКО копию guest.py в своём учебном каталоге:
  - стоимость OSPF A-C с 50 до 15: исходным лучшим станет прямой путь;
  - LOCAL_PREF B с 200 до 50: исходным лучшим станет C.
Но проверки тоже должны отражать новое условие; просто закомментировать assert
означает убрать проверку, а не исправить механизм. Базовый запуск сначала
сохрани без изменений. После изменения можно обновить только свой образ:

  python3 build_vm.py "$task_vm" --repack \
    --kernel-deb "$task_vm/kernel.deb" --modules-deb "$task_vm/modules.deb" \
    --frr-deb "$task_vm/frr.deb" --yang-deb "$task_vm/yang.deb"

Ограничения: одна небольшая область OSPF, без DR/BDR на point-to-point;
три частные AS, без Internet route leaks, RPKI и iBGP. Отдельные Linux network
namespaces — логические маршрутизаторы одного гостевого ядра, не независимые
физические машины. Нет проверки производительности оборудования, реального
радиоканала или времени отказа в другой среде. Протокольные основы и ссылки
на Linux 6.8, RFC 2328/4271/8212/6996, FRR 8.4 даны в разделах учебника.
