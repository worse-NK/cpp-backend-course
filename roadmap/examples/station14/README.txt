СТАНЦИЯ 14. ОДИН ЗАПРОС ЧЕРЕЗ ДВА C++-ПРОЦЕССА

Это отдельный локальный учебный стенд, не настройка рабочего сервера.
Скачайте ВСЕ файлы этой папки с сохранением имён, включая metrics.hpp,
конфигурации и dashboard.json. Для чтения главы запуск не требуется.

1. ЧТО ПОТРЕБУЕТСЯ

Linux/WSL, Python 3.10+, Docker Engine и Compose v2, уже настроенные владельцем
машины. Если docker info возвращает отказ доступа, остановитесь: не добавляйте
sudo, не меняйте права сокета и не запускайте службы по указанию этой лаборатории.
Проверку Docker-окружения выполняйте в отдельной учебной VM.
Нужны интернет и несколько гигабайт свободной памяти/диска: первая сборка C++ SDK
и загрузка образов могут быть долгими. Лаборатория не арендует облачные ресурсы.

Версии: cpp-httplib 0.59.0, OpenTelemetry C++ 1.30.0, Collector Contrib 0.164.0,
Prometheus 3.15.1, Grafana 13.3.0, Jaeger 2.22.0, GCC 14.4.0/trixie.
CMake проверяет SHA-256 двух архивов. Это закрепление исходников, не обещание
побайтовой воспроизводимости apt-пакетов или идентичного образа любой архитектуры.
Dockerfile намеренно оставляет инструменты сборки: это диагностический стенд,
а не оптимизированный production-образ. Нельзя публиковать его порты в интернет.

2. КАРТА

curl/helper -> 127.0.0.1:18140 -> api:8080 -> worker:8080
Prometheus -> api:8080/metrics и worker:8080/metrics
api/worker -> Collector:4318/v1/traces -> Jaeger:4317
Grafana -> Prometheus:9090; браузер -> 127.0.0.1:13014

Порты Collector и worker не публикуются на хост. 0.0.0.0 в контейнере позволяет
обращаться к нему соседям; это не тот же адресный контекст, что 0.0.0.0 хоста.
SDK отправляет трассы; метрики здесь специально экспортируются простым классом
Metrics через текстовый /metrics. Не приписывайте этому классу API OTel Metrics.
Логи — JSON в stdout контейнеров, отдельное хранилище логов не устанавливается.

3. ПЕРВЫЙ ЗАПУСК

В новом локальном каталоге с файлами лаборатории:
  python3 lab.py init
  python3 lab.py start
  python3 lab.py status
  python3 lab.py check

init не перезаписывает существующий .env. В нём создаются случайное имя проекта,
метка владения и пароль Grafana. Не отправляйте .env в Git или переписку.
start/stop/pause/resume проверяют метки найденных контейнеров, томов и сети.
Helper фиксирует проверенный локальный Unix endpoint Docker на время команды,
а три значения из своего .env явно передаёт Compose поверх shell environment.
Запускайте стенд через lab.py, не заменяйте команды произвольным compose down.
check/traffic сверяют не только имя станции, но и случайный ID этого запуска
в X-Course-Lab-Run. Другая папка с новым .env не должна нагружать прежний стенд.
Эта метка защищает от случайной путаницы, а не заменяет аутентификацию.
Проверьте свободные порты 18140, 19014, 13014, 16614; при конфликте не останавливайте
чужой сервис. Поменять согласованные порты можно только осознанно во всём стенде.

Дождитесь доступности API, двух успешных scrape и данных после нагрузки:
  python3 lab.py traffic --mode normal --count 40 --rate 2

В Prometheus откройте http://127.0.0.1:19014 и выполните:
  up{job=~"course-(api|worker)"}
  sum(rate(course_requests_total{job="course-api"}[1m]))

Ожидается up=1 у обеих целей; скорость вычисляется по нескольким снимкам.
Это критерии ожидаемого результата, не заранее измеренные числа вашей машины.
В Grafana: python3 lab.py credentials, вход пользователем course с локальным
паролем; папка Course содержит готовую панель. Пароль выводится только этой
отдельной командой по запросу, не в обычном отчёте о состоянии.

4. СВЯЗАТЬ ЛОГ И ТРАССУ

  python3 lab.py logs
  python3 lab.py traffic --mode slow --count 20 --rate 2

helper печатает X-Course-Trace-Id из ответа. Откройте Jaeger на
http://127.0.0.1:16614, найдите trace ID либо сервис api. Ожидается серверный span
GET /work, его клиентский GET /step и серверный span worker с одним trace ID.
Доставка из разных процессов асинхронная и пакетная: первый снимок может
содержать только часть трассы. Перечитайте тот же ID после небольшой паузы,
прежде чем объявлять span потерянным. Ограничьте ожидание; если часть не появилась,
проверьте exporter и Collector — полная доставка не гарантирована одним HTTP200.
Медленный режим добавляет 200 мс в worker. Это намеренная задержка сценария;
полное время API не обязано равняться ровно 200 мс. Ищите дополнительные интервалы.
Jaeger хранит трассы в памяти: перезапуск удаляет их. Сохраните наблюдения до него.

5. ПРОВЕРИТЬ ОШИБКУ И АЛЕРТ

  python3 lab.py traffic --mode error --count 120 --rate 2

В этом договоре «успех» означает HTTP 200; остальные завершения — error.
«Хороший запрос» дополнительно укладывается в 300 мс внутри измеренного handler.
/healthz и /metrics исключены из этих счётчиков. Событие считается при завершении,
поэтому зависшая работа видна в inflight, но ещё не в счётчике завершений.
В Prometheus откройте Alerts. После достаточного числа scrape и 15 с непрерывного
условия CourseApiErrorRatio должен перейти в firing. Правило показывает факт
срабатывания; Alertmanager и отправка писем в эту лабораторию НЕ включены.
Нет трафика -> 0/0, а не «всё успешно». Панель может показывать No data/NaN.

6. ДВА РАЗНЫХ ОТКАЗА

Только свои компоненты, через helper с проверкой меток:
  python3 lab.py pause worker
  python3 lab.py traffic --mode normal --count 20 --rate 2
  python3 lab.py resume worker

API может оставаться доступным для scrape, хотя /work отвечает ошибками.
Сопоставьте up, error fraction, логи и трассу; дождитесь восстановления.

  python3 lab.py pause collector
  python3 lab.py traffic --mode normal --count 20 --rate 2
  python3 lab.py resume collector

Метрики и API могут работать, но новые трассы не дойдут до Jaeger. В SDK очередь
256 spans и одна попытка экспорта с timeout 700 мс; Collector имеет свою конечную
очередь. Они не являются журналом аудита и не гарантируют сохранение при падении.
Возобновление не возвращает уже потерянные spans. ForceFlush/Shutdown вызываются
при штатной остановке, но SIGKILL/авария не исполняют этот код.

helper — последовательный клиент с верхним ограничением частоты, до 300 запросов
и до 5 запросов/с. При медленном ответе фактическая частота падает. Это не модель
постоянного внешнего потока и не тест предельной производительности.

7. ОСТАНОВКА И ДАННЫЕ

  python3 lab.py stop

Удаляются только контейнеры/сеть текущего проекта; тома Prometheus/Grafana остаются.
В Jaeger нет тома — его трассы после остановки потеряются. Для осознанного удаления
своих учебных томов посмотрите COMPOSE_PROJECT_NAME в локальном .env и выполните:
  python3 lab.py purge --confirm-project ТОЧНОЕ_ИМЯ_ИЗ_СВОЕГО_ENV

Это удалит данные томов без восстановления. Сначала сохраните нужные отчёты.
Не используйте docker system prune, массовый down, удаление чужих томов или .env.

8. ОФЛАЙН-ВАРИАНТ

Полный детерминированный C++-разбор без Docker и сторонних библиотек:
  g++ -std=c++20 -Wall -Wextra -Wpedantic metrics_model.cpp -o metrics_model
  ./metrics_model

Ожидаемые входные наблюдения: 0.05, 0.10, 0.12, 0.30, 0.80 с; третье ошибочное.
Итог: ok=4, error=1, good=3; buckets 2/4/5/5; count=5, sum=1.370000, inflight=0.
Это проверка вычислений класса, не сетевого стека Prometheus.

Для сборки HTTP-примера без SDK допустимо COURSE_WITH_OTEL=OFF; trace_id тогда
явно равен disabled. Не выдавайте такой запуск за проверку Collector/Jaeger.


Выбор C++20 или C++23 для локальной CMake-сборки
------------------------------------------------
По умолчанию проект остаётся на C++20. Для сравнения режимов используйте
разные каталоги сборки; команды выполняются в каталоге этого проекта:

    cmake -S . -B build-cxx20 -DCOURSE_CXX_STANDARD=20
    cmake --build build-cxx20
    cmake -S . -B build-cxx23 -DCOURSE_CXX_STANDARD=23
    cmake --build build-cxx23

COURSE_CXX_STANDARD допускает только 20 или 23. CMake требует выбранный
стандарт без перехода на более ранний и отключает расширения языка. Уже
существующие build-каталоги, настройки lab.py и контейнерные образы команды
выше не меняют. В каждый новый каталог отдельно передавайте нужные флаги
необязательных адаптеров из инструкции выше и установите указанные зависимости.

Для отдельного компилятора добавьте при ПЕРВОЙ настройке нового build-каталога:

    -DCMAKE_CXX_COMPILER=/absolute/path/to/g++

Не подменяйте компилятор в старом CMake cache. Сам режим -std=c++23 не обновляет
стандартную библиотеку и не доказывает поддержку всех возможностей C++23.
Текущие базовые исходники сохраняют требования C++20; поддержку нужных функций
и совместимость зависимостей проверяют для конкретной сборки. Это не перевод
Docker-образов или внешних SDK на другую версию.

Основание выбора режима CMake 3.24:
https://cmake.org/cmake/help/v3.24/prop_tgt/CXX_STANDARD.html
https://cmake.org/cmake/help/v3.24/prop_tgt/CXX_STANDARD_REQUIRED.html
https://cmake.org/cmake/help/v3.24/variable/CMAKE_CXX_COMPILER.html
