Локальный рабочий процесс: UNIX-сокеты и передача открытого файла
================================================================

Это две полные учебные программы для Linux, C++20. Они связывают только
собственный процесс и его ребёнка; IP-соединений, root и настройки системы нет.
До fork программа однопоточная. Переносить произвольный C++-код после fork
в многопоточный сервер без разбора ограничений fork нельзя.

Скачай в один новый учебный каталог:
  ipc_common.hpp
  socketpair_stream.cpp
  descriptor_transfer.cpp
  CMakeLists.txt

Нужны уже установленные CMake >=3.20 и компилятор C++20. В этом каталоге:

  task_build=$(mktemp -d /tmp/course-unix-build-XXXXXX)
  cmake -S . -B "$task_build" -DCMAKE_BUILD_TYPE=Debug
  cmake --build "$task_build" --parallel 2
  ctest --test-dir "$task_build" --output-on-failure
  "$task_build/socketpair_stream"
  "$task_build/descriptor_transfer"

Точный stdout первой программы:
  reply: accepted job:41

Точный stdout второй программы:
  child_prefix=shared
  parent_tail=:41
  fd_cloexec=true
  credential_uid_match=true

Первая программа передаёт один запрос по SOCK_STREAM. Границу запроса задаёт
shutdown(SHUT_WR), а не количество send/read. Родитель сначала читает ответ,
потом вызывает waitpid. Протокол одноразовый: после SHUT_WR второго запроса нет.

Во второй программе SOCK_SEQPACKET сохраняет границы записей. Файл создаётся
после fork, поэтому ребёнок НЕ получил его наследованием. mkostemp создаёт
уникальный собственный файл в /tmp, программа сразу удаляет только его имя.
Открытый файл продолжает жить через FD. Никакие пользовательские пути программа
не принимает. Позицию общего описания открытия ребёнок меняет чтением shared;
подтверждение по сокету разрешает родителю читать оставшееся :41\n.

Сверь код с объяснением:
1. Какие копии концов socketpair закрывает каждый процесс?
2. Почему один send не обещает один read у SOCK_STREAM?
3. Чем shutdown отличается от close?
4. Почему основной процесс не может прочитать хвост раньше подтверждения?
5. Где MSG_CMSG_CLOEXEC, MSG_TRUNC, MSG_CTRUNC и RAII защищают приём?
6. Почему SCM_CREDENTIALS не заменяет прикладное разрешение на операцию?

Изменение для самостоятельной работы: замени содержимое файла на
shared:73\n и согласованно измени ожидаемый хвост. Порядок операций не меняй.
Повторно собери и проверь stdout. Не передавай чужие FD или секретные файлы.

Ограничения: маленькие блокирующие одноразовые обмены, известный доверенный
родитель, один рабочий, нет тайм-аутов внутри протокола и нет длительного
обслуживания. CTest ограничивает опыт 10 секундами. Это не библиотека IPC
для применения без изменений к произвольным недоверенным процессам.

Основания: Linux man-pages socketpair(2), unix(7), shutdown(2), send(2),
recvmsg(2), cmsg(3), dup(2), fork(2). В теории приведены прямые ссылки.
